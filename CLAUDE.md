# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Windows 11 app in Rust: "Morph ▸" submenu in the modern Explorer right-click menu that converts images, PDF, video/audio, Office docs.
**`SPEC.md` is the source of truth.** Don't change scope, UX, libraries or license without discussing in an issue first. Milestones: SPEC §12.

## Commands (PowerShell, repo root)

```powershell
# one-time per machine (~20 min): native HEIC/AVIF decoders, static
vcpkg install --triplet x64-windows-static --x-install-root="$env:VCPKG_ROOT\installed"
.\scripts\fetch-deps.ps1                     # once per checkout/worktree: pinned PDFium + FFmpeg → vendor\ (git-ignored)
cargo build --workspace                      # debug build
.\target\debug\morph-cli.exe convert <files> --action image.convert --format webp   # try converters without the GUI
cargo test --workspace                       # all tests
cargo test -p morph-core --test pdf_split_merge          # one integration test file
cargo test -p morph-core scheduler::tests::unsupported   # one test by name filter
cargo test -p morph-core -- --ignored        # opt-in tests: need MS Office, open Explorer/tray, or perf (release)
.\target\debug\morph-cli.exe actions         # list action IDs + default options JSON (also: options <id>, engines)
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all
.\packaging\dev-register.ps1                 # build, stage layout\, register loose MSIX (Developer Mode), restart Explorer
.\packaging\dev-register.ps1 -Unregister     # remove the dev package
```

Engine-dependent tests print `SKIPPED: …` and pass when LibreOffice is missing. Overrides for testing engine detection: `MORPH_SOFFICE=<path>`, `MORPH_NO_MSOFFICE=1`, `MORPH_NO_LIBREOFFICE=1`, `MORPH_FFMPEG_DIR=<folder with ffmpeg.exe/ffprobe.exe>` (worktrees can point at the main checkout's `vendor\ffmpeg` instead of re-downloading). Fixtures (incl. Unicode names, broken files) live in `tests/fixtures/`; image ones are regenerated by `scripts/make-fixtures.ps1`.

Before opening a pull request: `cargo fmt --all`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`. Manual checks for the Explorer menu and the app: `docs/manual-tests.md`.

## Layout

- `crates/morph-formats`: tiny shared tables (extensions, menu, action IDs, CLSID, paths, request file). Linked into the shell DLL: keep deps minimal.
- `crates/morph-shell`: `morph_shell.dll`, IExplorerCommand COM server.
- `crates/morph-app`: `Morph.exe`, Slint GUI.
- `crates/morph-core`: job model, scheduler, converters (`image/`, `pdf/`, `office/`, `text/`). No UI.
- `crates/morph-cli`: `morph-cli.exe`, same core from the command line.
- `packaging/`: MSIX manifest template + dev scripts. `docs/manual-tests.md`: manual test checklist.

## How a conversion flows (SPEC §5.2)

1. `morph-shell` builds the menu from `morph_formats::menu` (extension checks only), writes a request JSON (`morph_formats::request`) to `<LocalData>\requests\`, and activates `Morph.exe --request <path>` via the AUMID. `<LocalData>` resolution lives in `morph_formats::paths` so DLL and exe agree.
2. `morph-app` reads + deletes the request, shows the options window, builds a `morph_core::Job`.
3. `morph_core::scheduler::run_job` routes each `Task` to a queue (rayon CPU pool with a memory budget, or the serial Office queue) and streams `Event`s back over a channel.

Adding an action touches: action ID const (`morph_formats::actions`), menu entry (`morph_formats::menu`), `morph_core::Action` variant + `Default` options struct (serde, defaults = Settings defaults), `scheduler::converter_for`, a `Converter` impl, the app's options UI, and both `strings.rs` files (`morph-app`, `morph-cli`: each binary's user-visible text lives only there).

## Rules that must never be broken

- Never modify, move or delete input files. Write to a temp file in the target folder, then rename. Collisions get ` (1)`.
- Shell DLL must never crash or slow Explorer: no `unwrap`/`expect` (crate denies them), `catch_unwind` on every COM entry point, extension-only checks, no file I/O except the cached config read.
- One failed file never stops a batch. Every error: plain-English message + copyable details.
- All UI text in English, in one place. App name only in `morph_formats::APP_DISPLAY_NAME` + the manifest.
- SPDX header `// SPDX-License-Identifier: GPL-3.0-or-later` in every source file.
- Check the latest crate version and docs (context7 / docs.rs) before adding a dependency.

## Fixed IDs

- Root command CLSID: `{BCC8EAF0-12A9-452A-87A5-B52F2DCC77F5}` (`morph_formats::ROOT_CLSID_*` and manifest).
- Package identity name `OpenMorph.Morph`, publisher `CN=OpenMorph` (display name "OpenMorph"), application Id `Morph`; package family name `OpenMorph.Morph_<hash>` (see `docs/manual-tests.md`). Old dev identity `Morph.Dev` is removed by dev-register. These live in `morph_formats::{PACKAGE_NAME, PACKAGE_PUBLISHER, APP_ID}` **and** `packaging/common.ps1`; keep them identical. The DLL computes the package family name and AUMID from them (it may run inside explorer.exe without identity).

## Gotchas

- Paths with spaces can break some native builds (vcpkg, C toolchains). If one fails for no clear reason, try a checkout path without spaces (e.g. `C:\dev\morph`).
- Explorer keeps the DLL loaded: restart Explorer after rebuilding `morph-shell` (dev-register does it).
- Static C runtime (`.cargo/config.toml`: `+crt-static`): vcpkg deps must use the `x64-windows-static` triplet (/MT). A `RUSTFLAGS` env var replaces the config's rustflags, so it must include `-C target-feature=+crt-static` too.
- Windows PowerShell 5.1: `Set-Content -Encoding utf8` writes a BOM; prefer the Write/Edit tools for source files.
